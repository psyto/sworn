# Claude Code 指示書 — CWF 用 Sworn デモ

## 目的

Colosseum Crypto World's Fair に提出する **3分以内のプロダクトデモ**を完成させる。
この映像で審査員に伝えるべきことは、ZKやEVMの実装詳細そのものではない。

> **支払い前の回答を売るなら、回答者は間違えたときに支払うべきだ。**

Sworn は、その「責任付きの送金前回答」をTempo上で実現する。視聴者が最初の60秒で、誰が何を尋ね、誰が何を保証し、回答が外れたら誰に資金が移るかを理解できる映像にすること。

## まず読むもの

- `video/DEMO.md` — 現在の構成、時間配分、検証済みの主張
- `video/PITCH.md` — ピッチとの役割分担と言葉遣い
- `README.md` — プロダクトの正確な挙動・制約
- `_submission/cwf-form.md` — 提出要件と開示事項
- `deployments/moderato.json` と `out/e2e/` — 画面に出すオンチェーン結果の根拠

`video/DEMO.md` の事実・数字・安全上の注意を、根拠なく変更しないこと。変更が必要なら、先に根拠ファイルを確認し、変更理由を記録すること。

## 登場人物（必ず明示する）

1. **支払いエージェント / 質問者（client）**
   - 支払いを行う側。
   - 「この送金を実行したら、受取人の残高は本当に500増えるか？」と尋ねる。

2. **回答サービス / 回答者（server）**
   - 送金前回答を提供・販売する側。
   - 「受取人は500受け取る」と回答し、その回答に対して自分の担保500をオンチェーンで予約する。

3. **チャレンジャー（client本人または第三者）**
   - 回答が誤りなら、Tempoの実行をZK証明で再実行して誤りを示す側。
   - 証明が通れば、回答者の予約済み担保は質問者へ支払われる。

「回答者」「質問者」を説明なしに使わない。画面では少なくとも最初の登場時に、`Paying agent (asks)`、`Preflight provider (answers + bonds)`、`Challenger (proves)` のように役割を表示すること。

## 必須のストーリー（0:00–1:00）

最初の60秒だけ見ても、次の因果が理解できなければならない。

1. **質問** — 支払いエージェントが送金前に「受取人に500届くか」と照会する。
2. **誤答と担保** — デモ用に不正回答へ設定された回答サービスが「届く、+500」と答え、自らの担保500をその回答に紐づけて予約する。
3. **実送金** — エージェントが500を送る。トランザクションは成功する。
4. **現実の結果** — しかし受取人の残高は `+0`、`ReceivePolicyGuard` は `+500`。成功ステータスと「相手に届いた」は違う。
5. **証明と支払い** — チャレンジャーがZK証明を提出し、誤答を証明する。予約されていた500が回答サービスから質問者へ移る。

画面では、3の **`transaction succeeded`** を先に見せ、その直後に **`receiver +0` / `ReceivePolicyGuard +500`** を大きく対比させること。これがSwornが解く問題の中心である。

## 残りの構成（60秒–3分）

- **正しい回答の保護:** 同じ仕組みでは、正しい回答を同じ証明で不当にスラッシュできないことを短く示す。
- **質問者の安全確認:** SDKが「質問内容、予約先、digest、契約・vkey、state witness」を確認する様子を示す。回答サービスが証拠を隠しても、質問者が証明を作れることを伝える。
- **技術的な根拠:** `tempo-revm` をSP1内で再実行し、Groth16証明をコントラクトが検証する流れを簡潔に示す。40/40の実トランザクション再実行結果は根拠として使うが、映像の主役にはしない。
- **結び:** 「支払い前回答を売るMPPサービスが、誤答の責任を自ら引き受けられる」という最初の顧客仮説を一文で示す。

## 映像と主張の制約

- すべてのオンチェーン数値、トランザクション、証明結果は実行済みのものを使う。演出用の成功画面・架空の残高・架空のタイムラインを作らない。
- proof生成は実時間約7分なので、**同じ実行の映像**をタイムラプスする。`time-lapse` と実際の所要時間を画面に表示する。別実行の録画やアプリの録画済み早送りを、ライブ実行のように見せない。
- 「testnet / Moderato」「unaudited」「ユーザー・売上・mainnetはいずれも未達」を隠さない。`production`、顧客、収益、完全補償を示唆しない。
- Swornは送金そのものを保証する仕組みではない。**名前付きブロック時点の、固定された送金についての回答**を担保化する仕組みである。状態変化後の送金、現実世界の納品、価格変動、全額補償は保証しない。
- 担保額は補償の上限である。回答者の担保500が予約されても、送金額全額を保険する主張に変えない。
- キー、秘密情報、環境変数の値を録画・コミット・出力しない。リモート送信が必要な収録は、`DEMO_ALLOW_REMOTE_TX=1` の安全注意を守ること。

- 0:60までに「質問者・回答者・誤答・Guardへの移送・証明・質問者への担保支払い」が一画面ずつ確認できる。
- 役割名と資金の流れを見なくても誤解しない字幕・ラベルがある。
- 実演に出る全ての主張を、`video/DEMO.md` のClaims and sourcesまたは同等の根拠へ対応付ける。
- 映像の編集手順、生成コマンド、入力データ、出力ファイル、検証結果を `video/` 配下に再現可能な形で残す。
- 実録画前に、編集案（台本、画面遷移、使用する実トランザクション）を提示してレビューを求める。秘密鍵操作・実送金・外部公開は、明示的な承認なしに実行しない。
